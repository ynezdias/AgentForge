# Deploying AgentForge (Render + Vercel)

| Piece | Host | Defined in |
|---|---|---|
| PostgreSQL | Render (managed) | `render.yaml` |
| FastAPI backend | Render web service (Docker) | `render.yaml`, `backend/Dockerfile`, `backend/docker-entrypoint.sh` |
| Next.js frontend | Vercel | Vercel project settings (root directory `frontend`) |

```
Browser ──HTTPS──► Vercel (Next.js pages + /api/backend proxy)
                     │  HttpOnly session cookie stays here
                     ▼  Authorization: Bearer <token>, X-Internal-Token
                   Render web service (FastAPI) ──private network──► Render PostgreSQL
```

The backend only accepts requests carrying `X-Internal-Token`, which only the Vercel proxy knows. Browsers never talk to Render directly.

On start, the backend container runs `alembic upgrade head`, creates demo accounts (if configured and not production), creates the bootstrap admin (if configured), and then serves on Render's `PORT`. No pre-deploy hook is needed, so it works on the free plan.

---

## Before you start

1. Push the repository to GitHub (Render and Vercel deploy from it).
2. Generate the shared proxy token and keep it somewhere private:
   ```powershell
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```
3. Decide the environment mode (`APP_ENV` in `render.yaml`):
   * **`demo`** (default): a hosted demo. Demo accounts and **Load sample workspace** are allowed. Use **new, strong demo passwords**, not your local ones; the site is public.
   * **`production`**: demo accounts, sample data, and the fake AI provider are refused. Set `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` (12+ characters) to create the first admin. Note: there is no UI yet for creating companies and company users, so production mode currently only supports the admin.

## 1. Render: database + backend

1. Render dashboard → **New** → **Blueprint** → connect the GitHub repository.
2. Render reads `render.yaml` and shows `agentforge-db` and `agentforge-api`. Fill in the prompted values:
   | Variable | Value |
   |---|---|
   | `INTERNAL_API_TOKEN` | The token from "Before you start" |
   | `GOOGLE_API_KEY` | Your Gemini API key |
   | `DEMO_ADMIN_EMAIL` / `DEMO_ADMIN_PASSWORD` | Admin demo login (strong password) |
   | `DEMO_COMPANY_EMAIL` / `DEMO_COMPANY_PASSWORD` | Company demo login (strong password) |
   `AUTH_SECRET_KEY` is generated by Render. `DATABASE_URL` is wired to the database automatically.
3. **Apply**. Wait for the first deploy. In **Logs** you should see `Running upgrade ...`, the accounts being created, and `Uvicorn running`.
4. Copy the service URL, e.g. `https://agentforge-api.onrender.com`. Check `https://<that-url>/health` returns `{"status":"ok"}`. Any `/api/...` URL should return `404` in the browser: that is the internal-token gate working.

## 2. Vercel: frontend

1. Vercel dashboard → **Add New** → **Project** → import the same repository.
2. **Root Directory**: `frontend`. Framework preset: Next.js (detected).
3. **Environment Variables** (Production):
   | Variable | Value |
   |---|---|
   | `BACKEND_URL` | The Render service URL from step 1.4, no trailing slash |
   | `INTERNAL_API_TOKEN` | **Exactly** the same token as on Render |
4. **Deploy**. Open the Vercel URL.

## 3. First sign-in

1. Open `/login/admin`, sign in with the demo admin.
2. On the Oversight page choose **Load sample workspace** (demo mode only).
3. Sign out, open `/login/company`, sign in with the demo company user, and run **AI Invoice Exception Resolution** on an exception invoice.

The session cookie is automatically `Secure` on Vercel because requests arrive over HTTPS.

## Smoke test checklist

- [ ] `/` loads; response has `X-Frame-Options: DENY`.
- [ ] `https://<render-url>/health` → 200; `https://<render-url>/docs` → 404; `https://<render-url>/api/v1/invoices` → 404.
- [ ] Admin and company sign-in work; each portal rejects the other's account.
- [ ] An AI run reaches **Needs approval** with a Gemini recommendation; approve completes it.
- [ ] **Audit log** shows the actions with the right people.

## Operating notes

* **Cold starts.** Free Render services sleep after inactivity; the first request can take about a minute. The proxy allows 60 seconds per request.
* **Free database expiry.** Render's free PostgreSQL expires after 30 days. Upgrade the database plan to keep data.
* **Rotating the proxy token.** Change `INTERNAL_API_TOKEN` on Render and Vercel together, then redeploy both.
* **Rotating `AUTH_SECRET_KEY`** signs everyone out; that is the intended effect.
* **Gemini costs.** Every AI run calls Gemini. Share demo logins only with people you intend to.
* **Interrupted runs** are recovered at each backend start (`RECOVER_INTERRUPTED_ON_STARTUP=true`) and from the admin **Decisions → Needs attention** tab.
* **Rollback.** Both Render and Vercel can redeploy a previous build from their dashboards. Database migrations are additive; downgrade scripts exist but should be reviewed before running against real data.
